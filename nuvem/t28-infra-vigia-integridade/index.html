Vigia de integridade

Um script Python, só com biblioteca padrão, que avisa quando alguém troca um hook, um servidor MCP, uma permissão do Claude ou a permissão de um .env no servidor. Também resume as vulnerabilidades das dependências toda semana. Só avisa: não conserta nada e só escreve na própria pasta de estado.

28 testes verdes (também como não root) nenhum segredo na saída (testado) falha fechada formato do osv-scanner não verificado

O que ele confere

--checar
de hora em hora		SHA-256, dono e permissão de cada arquivo do ini, comparados com base.json. No JSON, compara só as chaves vigiadas (hooks, permissions, env, mcpServers, projects.*.mcpServers…); as outras chaves podem mudar sem aviso. No .env, compara hash e permissão; acima de 600 avisa sempre. Nas pastas de hooks, arquivo novo, sumido ou mudado avisa. Arquivo sumido, ilegível ou com JSON quebrado também avisa. O script e o ini se vigiam.
--aceitar "motivo"Regrava a base e anota em aceites.jsonl, que só recebe acréscimos: data, motivo, usuário e hash antes → depois. Recusa sem motivo e recusa com item sumido ou ilegível.
--deps
segunda 7h		Roda o osv-scanner em cada pasta e resume por projeto, separando ALTA e CRÍTICA (aliases contam uma vez). Sem o binário, escreve uma linha e sai com 3.

Como sai o aviso

INTEGRIDADE MUDOU · 4 nova(s): .env, novo.sh, settings.json · detalhe em …/relatorio.md
  …/.env: .env com permissão 644 (máximo 600)
  …/hooks/novo.sh: arquivo novo na pasta vigiada (sha 73cb3858a687, 0644)
  …/settings.json: chave vigiada mudou: hooks (sha 44136fa355b3 → 4ca7ddfbffa0)
INTEGRIDADE OK · 4 diferença(s) já avisada(s) hoje, pendente(s) de --aceitar

Com --resumo, sai só a primeira linha. Códigos: 0 = nada novo, 1 = mudou, 2 = erro do vigia (sem base, base corrompida, ini ausente, trava ocupada) e, no --deps, 3 = sem osv-scanner. A mesma diferença avisa uma vez por dia; uma diferença nova no mesmo dia avisa na hora.

Testes (pytest, árvore sintética, sem rede)

Base nova, chave vigiada mudou, chave ignorada (não avisa), curinga de projeto pega MCP novo, JSON quebrado, hook novo, hook mudado e sumido, .env com 644 (e o aceite não cala isso), arquivo sumido, arquivo ilegível, ini mudado, aceite com motivo, aceite sem motivo (três formas), aceite com item sumido, repetição no mesmo dia (cala; diferença nova no mesmo dia e o dia seguinte avisam), avisos.json estragado (volta a avisar), base apagada com livro e base corrompida (erro), "não escreve fora do estado nem conserta", fixture do osv com 1 crítica, osv falso de ponta a ponta e osv ausente.

Limitações

  • O formato JSON e os códigos de saída do osv-scanner vêm de memória da documentação e não foram conferidos aqui (nesta tarefa não houve busca na web). O comando fica no ini; para a v2, use osv-scanner scan source --format json -r {pasta}.
  • Os nomes das chaves do ~/.claude.json no exemplo precisam ser conferidos contra o arquivo real.
  • Root pode trocar o vigia e a base juntos. O livro e o aviso mostram a troca, mas não a impedem.
  • Só Linux (usa fcntl, pwd, grp).
