O que mudou

  1. Fonte WebDAV como padrão. PROPFIND com Depth: 1 em …/public.php/webdav/Dados/Cadastros/CNPJ/ lista as pastas AAAA-MM e, dentro do mês, cada zip com o tamanho. O GET usa Basic auth com o token do link e senha vazia. O download nunca pede Range: em qualquer falha (rede, HTTP, tamanho diferente do anunciado, zip que não abre) o parcial é apagado e o arquivo vem de novo do zero, até 6 vezes, com espera de 2, 4, 8, 16 e 32 s. Só depois de conferido o arquivo ganha o nome final.
  2. Mês mais recente automático. Sem --mes, vale o mês mais novo que esteja completo: tem Empresas, Estabelecimentos, Sócios e Simples, nenhum arquivo com 0 byte e pelo menos tantas partes de cada tipo quanto o mês anterior. Um mês ainda subindo é pulado com aviso. Se o mês já tem top1000.csv, rodar não faz nada (use --refazer), e quando processa um mês novo já grava o novidades.csv contra o mês anterior da mesma pasta.
  3. --fonte-local mantido. Lê os zips de uma pasta e nunca apaga os originais. Se a pasta se chama 2026-10, o mês sai do nome. Serve para os zips que o baixar-e-rodar.sh já trouxe.
  4. Extras pequenos. python pipeline.py listar mostra os meses e os arquivos com tamanho. --manter-zips guarda os zips em saida/<mês>/zips, e uma rodada seguinte reaproveita os que estão inteiros. Na v1 essa opção não funcionava, porque a limpeza final apagava a pasta onde os zips ficavam. --webdav e --token servem para quando a Receita trocar o link.

Para rodar no PC

pip install duckdb requests pytest
python -m pytest -q                       # 11 testes, ~10 s
python pipeline.py listar                 # confere a fonte: meses e arquivos com tamanho
python pipeline.py rodar --dir C:/Users/loren/ozav-cnpj/saida
# com os zips que o baixar-e-rodar.sh já baixou:
python pipeline.py rodar --fonte-local C:/Users/loren/ozav-cnpj/zips/2026-10 --dir C:/Users/loren/ozav-cnpj/saida

Para a rotina semanal, agende sempre o mesmo python pipeline.py rodar --dir …. Na semana sem mês novo ele só avisa que o mês já foi processado.

Como o teste imita a Receita

  • O servidor falso roda em 127.0.0.1 dentro do pytest, sob /public.php/webdav/Dados/Cadastros/CNPJ/, e responde 401 sem o token certo.
  • O PROPFIND devolve 207 Multi-Status no formato do Nextcloud, inclusive o propstat 404 de tamanho que ele manda para pastas. Os nomes vêm codificados na URL (espaço e acento).
  • Ele publica 2026-09 e 2026-10 completos, um 2026-11 pela metade e um arquivo solto. O pipeline escolhe 2026-10 e, quando 2026-11 completa, passa a escolher 2026-11.
  • Ele pode derrubar a conexão no meio de um zip ou mandar um zip menor que o anunciado. O teste confere que o arquivo final é idêntico ao original, que houve um GET a mais por falha e que não sobra .part.
  • Os zips são os mesmos dados sintéticos da tarefa 1. Nenhum número desta página vem da base real.

Limitações e o que não deu para verificar

  • Bloqueado nesta sessão: arquivos.receitafederal.gov.br (HTTP 403 no proxy de saída). O python pipeline.py listar rodado daqui falhou exatamente nesse domínio. O endereço e o token foram usados com sucesso no PC pela conversa 00, mas não foram conferidos daqui.
  • O servidor falso imita o formato do Nextcloud, mas não é o servidor da Receita. Se o caminho ou o token mudarem, a listagem para com uma mensagem clara (401, 403 ou 404) e basta passar --webdav e --token novos.
  • Não verificado: onde fica a base de regime tributário no WebDAV. Com --regime, o código procura uma pasta com "regime" no nome ao lado de CNPJ/ e um zip com "real" no nome. Se não achar, tenta o endereço antigo e, se falhar, segue sem regime.
  • Um arquivo que ainda está subindo e já aparece na listagem com tamanho parcial não é detectado. A regra de mês completo reduz esse risco, mas não zera.
  • Privacidade igual à tarefa 1: nome de sócio PF nunca é gravado e do e-mail só o domínio. O teste de ponta a ponta confere isso byte a byte.
